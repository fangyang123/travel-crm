# 旅游客户信息系统

一个**纯前端 Web 应用**，配合 **GitHub（代码托管）+ Supabase（云端 Postgres 数据库）** 使用。
数据存在云端、从任意浏览器可访问，无需自己搭服务器。

> 数据库**复用「复盘系统（astock-review）」同一个 Supabase 项目**，无需新建项目、无需改连接配置。

## 功能

- **新建客户（生成订单）**：填写姓名 + 18 位身份证号；系统自动校验身份证有效性，并解析出生日期、性别，自动建好跟进单。
- **订单状态跟踪**：每个客户为一张订单，状态 = `跟进中 / 成功 / 失败`，可随时标记。
- **每日待跟进汇总**：`今日工作台` 自动列出「今天还没跟进过的跟进中客户」，按创建先后排序，上班直接照着跟进。
- **超时自动判失败**：创建满 **15 天** 仍 `跟进中` 的订单，打开页面时由系统自动判定为 `失败`（标注「超时」），无需手动处理。
- **当日生日客户**：根据身份证出生日期（公历）自动匹配今天过生日的客户，方便送上祝福。
- **跟进记录**：每次跟进可填备注，订单详情里按时间线回看全过程。
- **导出 CSV**：客户管理页可一键导出当前数据。

## 快速开始（只需跑一次建表）

数据库已就绪，连接配置已写进 `index.html`。你只需：

1. 进入 Supabase 后台（同一项目 `ulgoozjkbngiqtovhfbf.supabase.co）→ **SQL Editor**。
2. 粘贴本仓库 `schema.sql` 内容 → 点 **Run**（只跑一次，会新建 `customers` 表）。
3. 用浏览器打开 `index.html` 即可使用。所有数据实时写入云端库，换设备/换浏览器都看得到同一份。

## 安全 / 隐私提示
- 身份证属于敏感个人信息。当前方案用 `publishable key` + 开放 RLS 便于个人使用（与复盘系统一致）；若多人使用或数据敏感，建议：
  1. 改用 Supabase Auth 登录（邮箱/密码），再用 RLS 按用户隔离数据；
  2. 对身份证号在写入前做脱敏或加密；
  3. 切勿把 `service_role` key 放进代码或提交仓库。
- 建议定期用「导出 CSV」做本地备份。

## 常见问题
- **连接出错 / 读不到数据**：确认 `schema.sql` 已执行、表名 `customers` 拼写一致、项目未暂停（免费项目长期不用会被暂停，去后台 Resume）。
- **身份证校验失败**：18 位含最后一位可能是 X（大写），系统已自动转大写，按真实证件输入即可。
